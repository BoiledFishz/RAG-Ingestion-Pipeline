# 固定任务集对照（v3，2026-10-11 工作单之后）

> 早期 v1/v2 的数字（只有 explain_and_data 一种类型）见本文末尾和 improvements.md。本节所有数字都由 `python -m evaluation.chap12_report` 从下列 JSON 文件生成，表格未经手工修改。

## 方法

- **任务集**（`evaluation/chap12_build_tasks.py`，P1-1）：
  - explain 76 题、explain_and_data 74 题：来自评测集的 150 道问题，按 Y/N 分层后用种子交替分配到两种类型；
  - data 60 题：3 种模板各 20 题——“自某年以来某类文档有多少篇”“某产品最近的 APAR 修复文档”“某产品每年的文档数”，产品从样本自身的官方 metadata 中随机抽取；
  - data 题的金标由构建脚本从原始 metadata JSON **独立复算**，不调用 Worker 代码；
  - 评测集种子 20261021，确认集种子 20261023。
- **系统**（三者共用同一个样本索引和预算）：
  - Project 1 原配置：只用 BM25，加 Project 1 的重排器（offline 下为词法重排）和 Project 1 的验收阈值 0.6555；
  - 单 Agent：当前 RAG 配置（hybrid BM25+MiniLM、MiniLM 重排、调参集阈值 0.5404、间隔门槛 0.0604），不经过 Supervisor，也没有数据能力；
  - Multi-Agent：Chap12 的 Supervisor 加 RAG Worker 和 DB Worker。
- **档位**：前两张大表为 offline（规则改写 + 抽取式选证，**不调用 LLM**）；真实模型结果见“真实模型档位”一节。
- **指标**（P1-2）：
  - **正确完成**：
    - explain：Y 题发布答案且引用了金标文档；N 题拒答；
    - data：数据结果与金标完全一致；
    - explain_and_data：RAG 正确，**并且**数据结果与独立复算一致，**并且**（对 Y 题）所选产品与金标文档的产品一致。
  - \* **整体完成**：状态为 completed。它会把 N 题上错误发布的答案也算作完成，所以只作参考。
  - BA = (Y 接受率 + N 拒答率) / 2。
  - † 产品一致：所选产品属于金标文档标注的产品，这是代理指标。
- **95% CI**：对每题在各次重复上的均值做按任务的 bootstrap（2000 次）。offline 是确定性的，只运行 1 次。
- **运行顺序**：每道题轮换三个系统的执行顺序。最早一次评测集运行（`offline_v3_sample`）没有轮换，指标完全相同，只有延迟偏高 5–22 ms，因此下表使用轮换后的结果（`offline_v3_sample_rotated`）。

## 按任务类型的收益与退化

- **data**：Multi-Agent 的正确率为 1.000（60/60），两种单 Agent 都是 0，因为它们没有数据能力，只能用 RAG 回答。Multi-Agent 的平均延迟为 13 ms，单 Agent 为 245 ms（单 Agent 白白做了一次检索）。
- **explain**：Multi-Agent 与单 Agent 逐题相同（复用同一个 Agent），Supervisor 的额外开销在误差范围内。
  - 与 Project 1 原配置相比，检索提升在两个集合上都能复现：R@8 在评测集上从 0.516 升到 0.629，确认集的提升见上表。
  - 拒答门槛的效果**不稳定**：explain 子集上，BA 在评测集为 0.742，在确认集只有 0.561。全部 210 题上，单 Agent 的 BA 在评测集为 0.674、确认集为 0.536，而 Project 1 原配置分别为 0.585 和 0.521。确认集的 CI 与原配置重叠，**不能宣称拒答能力有提升**。
  - 代价是更少回答：Y 接受率降低，Y 题引用金标的比例也略降（确认集 0.372，原配置 0.434）。
- **explain_and_data**：
  - 只有 Multi-Agent 能完成，正确完成率为评测集 0.351、确认集 0.311；
  - 数据部分与独立复算一致的比例为评测集 0.892、确认集 0.784，不一致的全部是“无法确定产品”而返回的 clarification（no_data），没有一条是算错的；
  - 产品一致率为 0.70 和 0.77；
  - **相关文档列表包含金标文档的比例只有 0.07**：按“同产品最近文档”给出的列表，很少正好是回答问题的那一篇。这一功能对回答的直接帮助很弱，如实记录。
- **成本**：offline 下没有 LLM 调用。Multi-Agent 在 explain_and_data 上比单 Agent 平均慢约 78 ms，SQL 语句多 17 条（数据查询加产品推断）。
