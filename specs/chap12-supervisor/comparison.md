# 固定样本对照：单 Agent vs Multi-Agent（v1，第一轮）

> 第二轮（v2）的改进与结果见 [improvements.md](improvements.md)；下文保留 v1 原始数字。

## 运行条件

- 任务集：150 题，每题的任务都是“解释问题，并给出该产品在知识库样本中的文档数”。
- 运行档位：`offline`（规则改写 + 抽取式选证 + 词法重排，不调用任何模型），这是我在本机 Linux 环境中实际完成的一次运行。
  原始记录：`enterprise-ai-agent/evaluation/chap12/results/offline_20261011/`（`runs.jsonl`、`summary.json`）。
- **真实模型（Ollama qwen2.5:7b + nomic 重排）的运行还没有做。** 运行命令见 PR 描述，结果写到新目录，不覆盖本次记录。
- 两个系统共用同一个 RAGAgent、检索器、阈值和预算。单 Agent 就是直接调用 Project 1 的 RAGAgent。

## 结果（offline，n=150）

| 指标 | 单 Agent | Multi-Agent |
| --- | --- | --- |
| 整体完成（技术解释 + 数据都完成） | 0/150（无法提供数据部分） | 35/150 = 0.233 [0.173, 0.307] |
| 整体 partial / failed | 82 / 0（另有 68 个 no_data） | 71 / 44 |
| RAG 部分 completed / no_data | 82 / 68 | 82 / 68（与单 Agent 相同） |
| Y 题发布答案 | 71/123 = 0.577 | 71/123 = 0.577 |
| Y 题金标文档被引用 | 47/123 = 0.382 [0.301, 0.470] | 相同 |
| Y 题正文 token F1（未发布记 0） | 0.195 | 0.195 |
| N 题拒答（代理指标） | 16/27 = 0.593 [0.407, 0.755] | 相同 |
| 数据结果产出 | 不支持 | 59/150；91 题未识别出产品（clarification_required） |
| 数据结果与独立复算一致 | — | 59/59 [0.939, 1.0] |
| 延迟 mean / p50 / p95（ms） | 257 / 240 / 392 | 304 / 281 / 472 |
| LLM 调用 / token | 0 / null | 0 / null |

## 解读

- **收益**：Multi-Agent 增加了一项单 Agent 做不到的能力，即可以独立复算的数据结果（59/59 与独立复算一致）。部分失败也会显式标出，不会被当成空成功。
- **没有变化**：RAG 部分逐题完全相同，因为复用的是同一个 Agent。回答质量没有提升，也不应宣称有提升。
- **代价**：offline 档位下平均延迟约增加 47 ms，主要是 DB 查询和汇合。真实模型下，由于两个 Worker 并行，延迟预期由 RAG 主导，但这一点尚未测量。
- **退化 / 限制**：61% 的题目无法从字面识别出目录产品，数据部分失败。因此 44 题的整体状态是 failed（RAG 无数据，且数据缺少产品）。
- offline 档位的 RAG 数字不代表真实模型的成绩；N 题拒答只是开放检索下的代理指标。
