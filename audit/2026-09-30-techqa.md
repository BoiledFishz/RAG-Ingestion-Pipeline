# TechQA 迁移与复验报告（2026-09-30）

本轮已将当前默认 Ingestion、Retrieval、Enterprise 与 Agentic 的知识内容统一到官方 IBM TechQA。三个服务的默认查询使用全量文档库；格式/OCR/Ragas 和单元测试使用可追溯官方子集。全量检索、Enterprise 310 题和真实 Agent 15 题均已执行完成，不能据此声称所有答案正确或所有作业生产标准均已满足。

## 数据证据与范围

- 原仓库：[IBM TechQA](https://github.com/ibm/techqa)；归档来自该仓库链接的 [PrimeQA/TechQA](https://huggingface.co/datasets/PrimeQA/TechQA)。
- 官方归档 SHA-256：`6b094ef9a69718f727ce8d7e15c4d961e51032cefaa952e0d6af9d176d7ba118`。
- 流式检查全部 **801,998** 条记录；2 条空正文（`isg3T1016084`、`swg21325092`），**801,996** 篇有效且唯一文档。源文件检查见 [inventory](../evals/techqa_source_inventory.json)。
- SQLite FTS5 索引包含全部 801,996 篇；Qdrant `techqa_full_hash` 保留已有 2,826,591 个 Hash 向量 Chunk。Dense/Sparse 共享原始 chunk_id。
- training 600 题中前 60 题用于阈值校准；dev **310 题全部测试**；validation **20 题全部测试**，但与 dev 有重叠，不能算独立新留出集。没有宣称跑完 600 条 training 问答或对 80 万文档逐一调用 Agent。
- 41 篇官方文档、15 条原始训练题随 Git 提交；12 个 Markdown、1 个文本 PDF、1 个扫描 PDF 均从官方原文转换。出处、原文哈希和 CDLA 许可在 [manifest](../data/techqa/manifest.json)。无新增虚构支持文档或伪造黄金答案。
- 空/损坏文件、注入指令、虚构引用编号、超时模型替身及 `help` 模糊请求仅用于故障/控制流测试，不进入知识库或答案黄金集。

**评测协议边界：** TechQA 的 N 标签表示官方 DOC_IDS 候选池没有标注答案。这里的开放全库检索未把 DOC_IDS 或 ANSWER 传给检索器，因此 N 拒答指标只是标签代理指标，不能当作全库答案不存在的真实判定。

## 本轮修复

| 问题 | 改进与验证 |
|---|---|
| 默认入口混用合成数据 | 所有服务默认共享 `rag.techqa`；删除活动 AWS 合成文档、Agent knowledge/search 语料和旧合成结果；历史审计与 Git 历史保留 |
| 全量 Hash 召回弱 | 建立磁盘 BM25、RRF 融合，并用 nomic 对有限候选语义重排；优化 FTS 先取 rowid Top-k 再取正文 |
| nomic 输入不规范 | 区分 `search_query:` 与 `search_document:`；新格式库 `techqa_nomic_v3` 使用正确前缀 |
| 清洗吞掉命令参数 | HTML 清洗限定实际标签，保留原文 `<domain>`、`<instance>`、`<VARIABLE NAME>`；官方原文回归测试 |
| 上下文只有问题描述 | 最终 Top-k 后取回官方 Parent；优先保留完整 resolution 段落和命令条件；限制上下文预算 |
| 重排降级阈值尺度错误 | 降级保留检索排序，改用独立覆盖率阈值；不将 RRF 分数与语义分数阈值比较 |
| Agent 计划/质量评分失真 | DAG 驱动任务执行、限定 Agent 名称；正文与官方答案 Token F1 + 正确文档引用；来源文本不参与得分 |
| 真实 Critic 超时/输出过长 | 有界输出与上下文、Schema 校验、最多两次重试；错误逐轮记录，未通过明确 fallback；依赖故障不宣称通过 |
| 测试依赖本地私有语料 | 测试使用已提交官方原文；根/子项目独立进程运行，避免同名 Python 包冲突 |

此前修复的 Embedding 失败非零退出、异常后释放本地数据库锁、摘要截断检测、无候选不调用 LLM/重排、过滤不可覆盖和无效引用拒答，均纳入本次回归。

## 全量检索对比

310 次请求，160 条 answerable 用于文档命中指标；运行错误 0。MRR 范围 Top-10，Precision 为 Top-5 标注文档 Chunk 比例。

| 模式 | Hit@5 / 文档 Recall@5 | Hit@10 | MRR | Context Precision@5 | 平均检索 ms |
|---|---:|---:|---:|---:|---:|
| dense_hash | 0.13125 | 0.14375 | 0.09652 | 0.02625 | 599.2 |
| bm25 | 0.63750 | 0.68125 | 0.51647 | 0.12750 | 3138.3 |
| dense_rerank | 0.15625 | 0.16875 | 0.14074 | 0.03500 | 2032.3 |
| hybrid_rerank | 0.64375 | 0.67500 | 0.54709 | 0.12875 | 4214.5 |

Hybrid 相比 Hash Dense 的 Hit@5 从 13.125% 提升至 64.375%；BM25 自身已有 63.75%，增益主要来自新增词法召回。不能将 Hash Dense 当作成熟语义 Dense 基线。缓存和同机并行任务影响延迟，此表不是隔离性能基准。

[全量逐题结果](../evals/techqa_full/runs.jsonl)；[validation 20 题](../evals/techqa_validation/summary.json) 的 Hybrid Hit@5 为 0.72727，运行错误 0。

阈值仅由训练前 60 题得到，`python -m rag.techqa.calibrate` 可精确重现已提交配置；拒绝使用 dev/validation 校准。Dense+Rerank 0.703596，Hybrid+Rerank 0.651721。训练集 N 只有 11 条，拒答校准不充分。

## 真实 Agent 实验

llama3.2:3b，15 条官方训练题，查询全量库；每个版本 15 次运行。Planner 对同一官方问题重复 10 次。

| 版本 | 正文 Token F1 × 正确引用 | LLM Calls | 估算 Token | Latency ms | 严格 Failure Rate | 运行错误 |
|---|---:|---:|---:|---:|---:|---:|
| fixed | 0.1010 | 0.00 | 0.0 | 3487.7 | 0.933 | 0 |
| react | 0.1010 | 2.00 | 1761.2 | 3641.3 | 0.933 | 0 |
| single | 0.1010 | 2.00 | 1758.9 | 2688.9 | 0.933 | 0 |
| multi | 0.0945 | 4.80 | 4371.7 | 9938.6 | 0.933 | 0 |

Failure Rate 定义为正文 F1 未达到 1 或执行异常，不能与运行崩溃混淆，也不等于人工判定错误率。正文 F1 会惩罚长答案与语义等价改写；正确来源硬门控也会惩罚引用其他同样有用的官方文档。
Planner Schema 成功率 100%，非法 Agent 输出 0%，10 次为同一种计划形态。此结论只针对该固定问题；不能证明所有问题规划稳定。
Critic 轨迹：TRAIN_Q000、TRAIN_Q008 在一次重试后通过；TRAIN_Q005、TRAIN_Q006、TRAIN_Q013 在两次重试后仍未通过，明确 fallback 到已检索证据。未隐藏结构化输出无效、引用失败等问题。
整体质量偏低：TRAIN_Q001、TRAIN_Q005 等命中相似但非标注答案文档，部分题被阈值拒答；长原文抽取稀释正文 F1。**本轮没有证明 Multi-Agent 优于 Single Agent**；实测 Multi 质量更低、调用/Token/延迟更高。

## 仍未达到的边界

1. 全量 Qdrant 仍是旧 Hash 向量与兼容切片、标题摘要；未对全部 280 万 Chunk 执行真正语义 Embedding、RecursiveCharacterTextSplitter 和逐 Chunk LLM 摘要。严格按 Ingestion 全量生产标准验收时，这部分不能判定全部完成。新 PDF/Markdown ingestion 路径已实现这些能力。
2. 真实 Agent 流程跑通，但答案质量、拒答和 Critic 稳定性仍需改进，不能宣称达到生产级正确率。
3. 原始语料、全量索引未提交 Git；干净环境需按 README 下载校验并构建。提交的官方小样本足以离线单元测试，但不是全量库的替代。
4. 当前 Search Tool 搜索全量 TechQA，同源 BM25，非互联网搜索；因此比较体现策略/调用开销，不代表外部网页增益。
